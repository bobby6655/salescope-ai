# V3：复杂表格与多表数据准备

基础模块新增「数据准备」：先识别原表结构，用户核对转换结果后保存数据版本，再提问。旧CSV上传和政策监控继续可用。

## 使用步骤

1. 登录后进入「数据准备」，上传XLSX或UTF-8 CSV。多个文件分别上传并保存版本，随后关联。
2. 选择Sheet，展开原始预览，确认表头开始行、表头行数和结束行。合并表头会展开为层级字段名。
3. 可以点击模型建议结构；建议只填入配置，不自动保存或执行结算。样例不完整时手动调整。
4. 点击预览，检查行数、金额、候选合计行和类型异常。排除行号只能在确认后填写；总计行默认保留而非自动删除。
5. 交叉表可勾选横向列，指定期间和值字段，重新预览转长表。空值不判零。合并数据区需要明确填写向下填充字段，不自动填充。
6. 必要时展开类型/单位JSON。支持number/string/date/auto；multiplier明确元/万元换算，unit记录目标单位；带单位的原数值必须用sourceUnit确认原单位。编号保留文本。转换异常会阻止确认。
7. 填版本名称和「一行代表什么」，勾选核对后保存并分析。分析接口从服务端读取确认版本，不采用前端伪造的原表。
8. 多表关联选择左右版本和完整键，可推荐候选键；确认业务含义后预览。展示关联前后行数、未匹配和左侧金额。一对多须核对左侧指标重复，多对多被拦截；不自动模糊合并名称。
9. 历史分析关联数据版本，可点击「基于此数据版本继续分析」恢复原版本；查看历史本身不改当前输入。旧V2历史没有原数据版本引用，不能完整恢复。

## 实现与边界

- Node保留登录、游客权限、账号隔离和API；游客不能访问工作区。
- Python 3.11独立进程按请求执行，Node设置45秒超时及32MB输出限制。没有开放模型生成Python或任意SQL执行。
- openpyxl读取所有Sheet和合并结构，不执行公式/宏/外部链接；公式仅读取已有缓存值，缺缓存会保留缺数。
- LangGraph编排结构标准化→DuckDB质量校验；原有分析Agent继续负责模型动作循环，增加query_workspace受控DuckDB工具，支持最多8个分组字段和8个聚合指标。此次没有把整个分析Agent迁入LangGraph。
- 转换前文件、Sheet、行号、交叉表值列及关联来源保存在账号工作区；版本不可覆盖，生成新版本。
- 工作区存储位于本地账号目录workspaces，Git/Vercel不包含原文件、私有版本或依赖环境。没有迁移保密归档。
- 每文件6MB，Sheet最多20000行/160列、最多30个Sheet；解压上限80MB，转换和关联结果最多20000行。图片、xls、加密/损坏文件和任意合同解析不属于本版。
- 日期/ID/指标含义仍需人工确认，支持复杂结构不等于任意文件零确认正确分析。

## 安装、部署与检查

`npm run setup:v3` 使用uv安装Python 3.11及锁定依赖到runtime-data/v3-python。可通过V3_PYTHON指定已经装好依赖的Python。依赖版本在server/v3/requirements.lock，不上传虚拟环境。

本机Git更新在切换后端之前安装/检查独立V3环境，通过V3_PYTHON让新版本可用。Docker安装Python虚拟环境及锁定依赖；GitHub CI同步验证。前端仍在Vercel，后端仍依赖电脑在线。

`npm test`包含工作区版本、隔离、伪造输入、历史继续检查；`npm run check:v3`验证复杂Excel、总计、空值、单位、填充、关联及受控查询；`npm run check:v3-browser`验证页面准备/确认/查询/历史继续/窄屏，使用独立账号和模型桩。实际模型连通需额外验收。
