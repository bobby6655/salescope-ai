# SaleScope AI 使用说明

适用版本：2026-11-03 游客与历史功能版。

SaleScope AI 提供两个独立模块：基础数据分析用于分析单张表；政策监控用于关联客户base、每日消耗和激励规则，查看达成情况与增量ROI。

## 1. 登录与快速体验

1. 打开 [工作台](https://bobbyyang.online)，无需登录即可游客体验；上传自己的文件及保存历史时，点击「登录」并输入管理员提供的账号密码。
2. 登录后，从左侧导航选择模块。手机上使用页面顶部的模块导航。
3. 首次体验政策监控，点击「政策达成复盘」，无需上传即可查看模拟数据。
4. 选择一名销售或一个客户，查看达成率、ROI和消耗过程；也可以在「销售政策问答」输入问题。
5. 使用完毕后点击页面顶部「退出」。

备用入口：[Vercel 登录页](https://bobbyyang-salescope.vercel.app/login)。两个域名的登录状态分别建立，换入口时可能需要重新登录。

当前前端已部署到Vercel，后端仍运行在管理员电脑上。电脑关机、休眠、断网或后端停止时，网页可能能打开，但登录、问答和导出会不可用。

## 2. 基础数据分析

### 2.1 上传表格

在「总览」「数据源」或「分析报告」点击「上传 CSV」，选择UTF-8编码的CSV文件。这个模块目前直接接收CSV；Excel请先另存为CSV。

表格第一行应为列名，一行对应一条业务记录。金额列使用数字，日期建议使用 `YYYY-MM-DD`，客户编号等标识字段保持为文本。不要把说明标题、合并表头或总计行混入明细。

也可以使用「切换样例表」体验销售、订单或广告投放等不同表结构。切换数据会清空当前分析与对话；刷新页面后如需分析自己的表，请重新确认当前数据源；已保存的结论可在「历史分析」查看。游客只可选择模拟样例，不能上传文件。

### 2.2 检查字段和口径

进入「数据源」，依次检查：

- **字段类型与质量**：确认日期、数值、文本类型；查看空值、类型异常和重复行提示。
- **业务含义映射**：需要用「收入」「日期」等业务简称提问时，可指定对应列。直接按真实列名提问则不必映射。
- **数据预览**：确认前20行与原表一致。

客户ID被识别为金额、日期被识别为文本时，先修改字段类型。系统不会自动删除重复记录；缺失值也不会自动当成零。

### 2.3 看总览与提问

「总览」可选择「概览指标」「日期字段」「比较维度」，查看合计、月度趋势及分组比较。

在底部输入框输入问题，按回车或点击发送。尽量写清指标、时间范围和比较维度，使用表中的真实列名。例如：

> 按专项比较2026-09-25到2026-10-07的消耗变化，说明整体涨幅、各专项增量贡献，以及哪些专项拖累增长。

> 按日期画消耗折线图，并指出变化最大的日期。

> 哪个专项增长率最高？哪个专项贡献的新增消耗最多？请分别排行。

字段不明确时，助手可能追问；补充条件后继续分析。查看「分析报告」中的最终答案、依据表和工具执行过程，确认比较窗口、单位及计算范围。增长率最高与新增金额贡献最大可能是不同专项。

生成的图表下方有SVG文件链接，可打开并另存。当前基础模块没有统一的完整报告下载按钮。

### 2.4 自动评测

进入「自动评测」，点击「开始评测样例」。系统使用预设的销售、英文订单、广告投放样例运行题目，显示预期结果、实际答案及通过情况。

评测用于检查分析功能，使用固定样例，不是对当前上传表的业务结论进行评分。本地演示回退不计为真实模型通过。

## 3. 政策监控

### 3.1 默认模拟展示

默认材料为20个虚构客户、259条消耗记录，周期为 **2026-09-25至2026-10-07，共13天**。包含达一档、达二档、未达成、下降、封顶、零现金、缺明细、编外客户及期外记录等测试情形。

在截止日为2026-10-07、未筛选客户、框架12%、渠道8.5%、不确认缺行视零时，预期结果为：

| 项目 | 预期值 |
|---|---:|
| base客户数 | 20 |
| 匹配消耗客户数 | 19 |
| 一档及以上客户数 | 15 |
| 二档客户数 | 10 |
| 客户数达成率 | 75% |
| base加权达成率 | 77.11% |
| 获政策返货客户数 | 14 |
| 获返客户增量ROI | 4.081436（页面约4.08） |
| 缺客户日组合 | 16 |

这些金额与规则仅用于演示，不用于真实结算。此前真实数据已移到本地私有归档，不作为默认展示。

账号已有上传数据时，页面会读取该账号保存的政策输入；新账号没有输入时加载模拟数据。上传、重算后的政策输入会保存在后端，刷新不会自动恢复模拟数据。当前没有「一键恢复模拟」按钮，需要重新上传模拟两表和规则，或联系管理员恢复。

### 3.2 准备两张表

政策模块支持 `.xlsx` 或UTF-8 `.csv`。Excel读取第一个含数据的工作表，请把目标明细放在该工作表；不执行公式或宏。建议上传已计算为数值的明细。

**客户base表：一行一个客户。**

| 默认列名 | 含义 | 示例 |
|---|---|---|
| 客户 | 与消耗表关联的客户名称 | 模拟星河 |
| 属性 | 政策分层的客户类型 | 小游戏 |
| 行业分组 | 部门或行业分组 | 模拟华东组 |
| 负责销售 | 销售负责人 | 模拟销售甲 |
| base(万/日) | 基期日均cost6，万元/日 | 1 |

**每日消耗表：一行一个客户、一天。**

| 默认列名 | 含义 | 示例 |
|---|---|---|
| 日期 | 消耗日期 | 2026-09-25 |
| 客户 | 与base表一致的客户名称 | 模拟星河 |
| cost_6消耗(万) | 考核消耗，万元 | 1.8 |
| cost_4现金(万) | 现金消耗，万元 | 1.44 |

同一客户、同一天不能重复；如果源数据有多行，请先按客户和日期汇总。cost4、cost6不能为负，cost4不能大于cost6。客户名应一致，表中金额使用同一种万元口径。

列名不同，可在「政策规则与字段映射」中的字段映射JSON修改对应列名。若base表额外包含档位、增长门槛、返点等规则列，其数值必须与所确认的政策规则一致。

### 3.3 确认政策与导入

1. 分别选择「客户base表」和「客户每日消耗表」。
2. 展开「政策规则与字段映射（可确认、可修改）」。
3. 使用默认模拟规则，或将准备好的规则JSON完整粘贴到「政策规则JSON」。JSON中的比例使用小数，例如12%写成 `0.12`。
4. 如需从正文提取规则，将政策文件的正文复制到「政策正文」，点击「解析粘贴规则（不自动应用）」。这里目前是粘贴文本，不是上传政策附件。
5. 核对解析后的日期、客户类型、档位上下限、两档增速、返点和封顶系数。框架及渠道比例也需人工确认，不要只凭解析成功就认定全部合同条款已匹配。
6. 点击「关联并生成政策复盘」，使用所选两表和当前规则计算。

正文解析适用于同类二档增量现金封顶政策，不支持任意形式的激励规则。信息缺失时可能要求补充；复杂互斥、资格条件及其他结算条款仍需人工核验。

已有复盘时，编辑或解析规则不会立即更新结果；点击「应用口径并重算」才会按新规则更新当前已保存的两表。新选择的文件则须通过「关联并生成政策复盘」导入。

### 3.4 截止日、筛选与客户过程

- **截止日**：在政策开始日与结束日之间选择日期，点击「应用口径并重算」，查看截至该日的阶段结果。
- **框架/渠道返货率**：页面输入框按百分数填写，例如框架填 `12`，渠道填 `8.5`。修改后需重算。
- **缺行视零**：只有确认没有明细确实代表零消耗时才勾选；否则保持关闭，缺数显示待核验。
- **筛选**：可按销售、部门、部门×类型、客户类型、档位、达成状态或客户名筛选。KPI与分组表随筛选变化。
- **客户过程**：点击客户名称，或使用「选择客户查看消耗过程」，查看日度消耗、门槛、目标及缺口。

导入和重算会重置筛选与政策对话。筛选变化也会清空当前政策问答上下文。

### 3.5 理解达成率与ROI

同天数base消耗 = base日均 × 已统计天数。

增长率 = cost6合计 ÷ 同天数base消耗 − 1。

客户数达成率 = 达到一档及以上的客户数 ÷ 当前范围全部base客户数。

base加权达成率 = 达成客户base日均之和 ÷ 当前范围全部客户base日均之和。大客户权重更高，因此可能与客户数达成率不同。

现金率 = cost4合计 ÷ cost6合计；正增量现金 = max(cost6增量, 0) × 现金率。

默认政策返货 = min(正增量现金, base日均 × 二档增速 × 封顶系数 × 已统计天数) × 达成档位返点率。

框架返货、渠道返货分别按正增量现金乘以对应比例计算。达到二档使用二档返点，不叠加一档返点。

**获返客户增量ROI**只纳入政策返货大于0的客户：

> ROI = 这些客户的cost6增量合计 ÷ 这些客户的（政策返货 + 框架返货 + 渠道返货）合计。

分子和分母必须使用同一客户范围，不平均各客户ROI。封顶后按实际试算返货计算；无获返客户时显示「—」。当政策返货未封顶时，单客户分母可写为增量cost6 × 现金率 × 三项返点率之和；封顶后不能直接使用这个简化式。

例如「模拟曜石」虽达二档，但现金率为0，没有政策返货，因此不纳入ROI。「模拟萤火」触发政策返货封顶。

阶段监控按已统计天数计算进度，但客户过程中的全期目标仍覆盖完整政策周期。缺数时结果是基于已有明细的观测和试算，不代表正式结算。

### 3.6 政策问答与导出

可以直接提问：

> 模拟销售甲名下客户达成如何？哪些客户未达标？

> 模拟萤火为什么触发封顶？请展示计算过程。

> 总ROI的分子、分母分别是多少？哪些客户不纳入？

> 模拟星河这13天的消耗有什么变化？画日度趋势图。

> 哪些客户缺明细？编外客户和期外记录是否被排除？

问答会沿用当前筛选范围，除非问题明确指定其他范围。查看答案时同时核对所用范围、截止日和单位。

页面底部可下载Markdown复盘、客户达成CSV或完整JSON。**导出包含当前已保存输入的全部base客户，不随页面筛选缩小范围**；使用当前已应用的规则和截止日，尚未重算的编辑不进入导出。

## 4. 常见问题

| 情况 | 处理方法 |
|---|---|
| 无法登录或接口不可用 | 确认账号密码；必要时尝试备用入口，并联系管理员检查后端电脑与网络。 |
| 更新后要求重新登录 | 后端重启可能清除原登录会话，重新登录即可。 |
| 基础模块无法选择Excel | 先另存为UTF-8 CSV；政策两表才支持直接上传XLSX。 |
| 表格列名或类型不匹配 | 基础模块修正字段类型/含义；政策模块修改字段映射JSON。 |
| 政策解析失败 | 查看页面提示，补全日期、档位及计返公式后重试；也可直接粘贴已确认的规则JSON。 |
| 规则改了，结果没变 | 解析不自动应用，点击「应用口径并重算」；新文件须重新导入。 |
| 达成客户仍显示待核验 | 检查客户是否缺日明细；观测达成不等于数据已完整核验。 |
| 某客户ROI是「—」 | 查看是否有政策返货；未获返、零现金或无有效分母时不适用。 |
| 筛选后导出仍有全部客户 | 当前导出按完整已保存输入生成，页面筛选只影响展示与问答范围。 |
| 页面表格或日期图较宽 | 在表格、图表内部横向滚动查看完整内容。 |

不同账号的政策数据和生成文件分别保存；同一个账号的使用者共享该账号的政策输入。基础模块与政策模块独立，基础模块的「切换样例表」不会恢复政策模拟数据。

## 6. 历史分析（登录用户）

登录后，成功的基础分析和政策问答会自动保存；政策导入及重算会保存当时的复盘快照。澄清、失败请求和自动评测不作为业务历史保存。游客结论不长期保存。

点击导航「历史分析」，按模块、关键词和日期筛选记录，再点「查看」。详情可看当时答案、依据、工具步骤或政策口径，并下载历史报告、JSON和图表。历史记录在刷新和后端重启后仍然存在；查看历史不会修改当前数据，也不会重新调用模型。

历史图表使用独立副本。删除时先点「删除」，再点「确认删除」；只删除该记录及其历史图表，不删除当前上传。删除无法恢复。不同账号的历史独立，同一个账号的使用者共享历史。此前未保存的分析不补录，保密归档不导入历史。

游客每次会话有效2小时，最多接受10次分析；公共接口还有共享额度和并发限制。超过额度时可稍后重试或登录。游客不能修改政策、上传或运行自动评测。
