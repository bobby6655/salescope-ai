# SaleScope AI

## 一句话介绍

SaleScope AI 是一个帮助销售和运营人员看懂销售数据的 AI 分析工作台。

用户上传一张销售表，用普通话提问，系统会：

1. 理解用户想问什么。
2. 选择合适的计算方法。
3. 在真实销售数据上计算。
4. 检查计算结果。
5. 返回答案、计算依据和过程。
6. 需要时生成图表并保存下来。

面试时可以这样介绍：

> 我做的是一个销售数据分析 Agent。它不是让大模型直接猜答案，而是让大模型负责理解问题，本地程序负责真实计算，所以结果更可靠，也方便检查。

## 1. 它解决了什么问题

销售人员拿到 Excel 后，通常需要自己：

- 筛选日期、地区和产品；
- 计算销售额、利润和折扣；
- 做地区、产品和月份排名；
- 制作趋势图；
- 检查数据有没有错误；
- 把结果整理成汇报语言。

这些工作重复、容易算错，而且不会写公式的人不容易完成。

SaleScope AI 把这些步骤放在一个页面里，让用户直接问：

```text
去年总营收是多少？
哪个地区营收最高？
营收最高的前三个产品是什么？
哪个地区的平均折扣最高？
帮我画一下每个月不同地区的收入占比。
```

## 2. 为什么普通聊天机器人不够

普通聊天机器人可以生成一段看起来合理的话，但它不一定真的读了销售表，也不一定真的算过数字。

这个产品把工作分成两部分：

```text
大模型：理解问题，选择计算方法，必要时追问
本地程序：读取数据，执行计算，检查结果，生成图表
```

例如用户问：

```text
营收最高的前三个产品是什么？
```

大模型只需要生成一个查询计划：

```json
{
  "operation": "group",
  "metric": "销售额",
  "group_by": "产品",
  "order": "desc",
  "limit": 3
}
```

之后由本地程序真正完成分组、求和、排序和取前三名。

## 3. 产品的三个版本

### 第一版：固定问题

第一版先不追求“什么都能问”，而是预先准备几个固定问题：

- 总营收；
- 最高销售地区；
- 最高销售产品；
- 月度销售趋势。

用户只能从有限问题中选择。

这一版的重点是验证：

> 计算结果是否准确，页面流程是否能跑通。

### 第二版：AI 参与一次分析

第二版接入 Wanqing。

用户可以输入自然语言，大模型把问题转成 JSON 查询计划，本地程序再执行计划。

例如：

```text
哪个地区的平均折扣最高？
```

模型会识别出：

- 指标：折扣；
- 计算方式：平均值；
- 分组字段：地区；
- 排序方式：从高到低。

这一版的重点是让用户可以自由提问，而不是只能点击固定按钮。

### 第三版：真正的分析 Agent

第三版不再只做一次转换，而是让 Agent 逐步工作：

```text
理解问题
  ↓
尝试写出分析方法
  ↓
执行真实计算
  ↓
检查结果
  ↓
发现错误时修正
  ↓
继续分析或给出答案
```

第三版还支持：

- 多轮对话；
- 根据上一轮内容理解“按地区看”“再比较一下”等追问；
- 问题不完整时主动澄清；
- 识别是否需要柱状图或折线图；
- 生成并保存真实 SVG 图表；
- 自动评测 10 道题；
- 显示准确率和错题。

第三版更像一个真正的 AI 产品，因为它不只是回答一次问题，而是能够持续分析、发现问题并修正。

## 4. 每次工作的完整流程

### 用户提问

用户输入一句普通话问题。

### 模型理解

Wanqing 判断：

- 用户要算什么；
- 使用哪个字段；
- 是否需要筛选年份或地区；
- 是否需要分组；
- 是否需要画图；
- 信息是否足够。

如果信息不够，模型不会猜，而是先追问。

例如：

```text
用户：帮我看看表现。

Agent：你想看销售额、利润还是折扣？还可以按地区、产品或月份分析。
```

### 本地计算

程序只执行白名单里的操作：

- 求和；
- 分组；
- 平均值；
- 排序；
- Top N；
- 年份筛选；
- 地区筛选；
- 利润计算；
- 收入占比计算。

### 结果检查

程序会检查：

- 字段是否存在；
- 筛选后是否有数据；
- 数值是否有效；
- 分组结果是否为空；
- 用户说“前三个”时是否真的取了前三个；
- 用户要求柱状图时是否真的生成柱状图。

### 返回结果

页面固定展示：

- 最终答案；
- 计算依据；
- 一共执行了几步；
- 每一步做了什么；
- 如果出错，错误原因是什么；
- 如果画图，图片保存在哪里。

## 5. 页面怎么演示

左侧有四个主要页面：

### 总览

展示总销售额、总数量、平均记录金额、数据质量、月度趋势、地区销售分布和热销产品排行。

### 数据源

展示当前文件、字段清单、数据预览、日期检查、销售额检查、折扣检查和重复记录检查。

### 分析报告

展示 Agent 当前分析问题、计算计划、真实计算步骤、错误修正记录、最终答案、计算依据和生成的图表。

### 自动评测

点击“开始自动评测”，系统会逐题运行 10 道题，并显示通过或失败、实际答案、标准答案、错误原因、总分和准确率。

评测结果会保存到：

```text
evaluations/latest.json
```

## 6. 面试时推荐演示的 5 个问题

### 问题一：总数计算

```text
去年总营收是多少？
```

展示按年份筛选并对销售额求和。

### 问题二：最高和最低

```text
哪个地区营收最高？
哪个地区营收最低？
```

展示按地区分组、排序和取最高或最低。

### 问题三：产品比较

```text
营收最高的前三个产品是什么？
```

展示按产品分组、从高到低排序、严格取前三个，也可以要求生成柱状图。

### 问题四：复杂指标

```text
哪个地区的平均折扣最高？
总利润是多少？
```

展示平均值计算、利润等派生指标，以及“大模型理解、本地代码计算”的分工。

### 问题五：画图

```text
帮我画一下每个月不同地区的收入占比。
```

展示按月份和地区做交叉分析，计算每个地区的月度收入占比，生成多系列折线图并保存到 `charts/`。

## 7. 为什么第三版更像真正的 AI 产品

第三版和普通问答产品的区别主要有四点：

### 不是只回答固定问题

用户可以用自然语言提问，不需要记按钮名称。

### 不是只调用一次模型

模型可以先理解问题，发现条件不完整时追问，生成查询计划，根据执行错误修正计划，最后再给答案。

### 不是让模型直接编数字

模型只生成计划，真实数字由本地程序计算。

### 结果可以被验证

每道题都有输入问题、查询计划、计算步骤、结果依据、错误信息和自动评测记录。

所以它不仅“能回答”，还能够说明答案怎么来的，以及系统是否真的可靠。

## 9. 如何运行

安装依赖：

```bash
npm install --registry=https://npm.corp.kuaishou.com/
```

配置 Wanqing：

```bash
cp .env.example .env
```

`.env` 需要配置：

```env
WQ_API_KEY=你的万擎API密钥
WQ_MODEL_ID=你的端点模型ID
WQ_BASE_URL=https://wanqing-api.corp.kuaishou.com/api/gateway/v1/endpoints
WQ_API_PATH=/chat/completions
WQ_TIMEOUT_MS=30000
WQ_DEMO_FALLBACK=true
```

启动：

```bash
npm run dev -- --host 127.0.0.1
```

打开终端显示的本地地址即可查看。

## 11. 当前边界

- 当前上传基础版支持 CSV，Excel 二进制解析还没有接入。
- 当前模型负责理解问题和生成计划，不负责直接生成数字。
- Wanqing 不可用时会进入演示模式，本地规则继续计算。
- 图表当前生成 SVG 文件。
- 目前数据量适合演示和中小规模分析，大数据场景需要改成后端任务和数据库方案。

## 面试收尾说法

> 这个项目的核心不是把一个聊天框接上大模型，而是把自然语言理解、真实数据计算、结果校验、错误修正、图表生成和自动评测串成一个完整闭环。这样用户得到的不只是一个答案，还能看到答案怎么来的，以及系统是否真的可靠。

## 12. ReAct 工具循环（2026-10-29）

现在模型可以连续选择查看数据、查询、绘图和完成答案。每次执行的真实结果和错误会回传给模型，模型据此决定下一步。最多 8 轮，总耗时限制为 180 秒；多轮用户对话继续保留最近 10 条消息。

例如：

```text
画一个每个月各地区收入的堆积柱状图。
再换成每个月的收入占比堆积图。
按地区和产品类别汇总利润，画一张堆积柱状图。
```

查询执行器支持组合两个维度，图表支持 `stacked-bar`。金额堆积图每根柱子的高度是当月总收入；占比图每月各系列合计 100%。当前样例 12 条记录覆盖 10 个有记录月份；无记录月份不会被推断为零收入。图片保存到 `charts/`，分析报告展示真实工具执行过程。

这种自主性覆盖现有工具能组合完成的问题。同比、预测、任意代码执行等能力仍需增加相应工具；不能承诺任何问题都能自动解决。答案引用本地计算结果，图表引用对应结果；失败不会被记录成真实模型成功。

行为验证：`npm test`。结构与样例数据检查：`npm run check`。生产构建：`npm run build`。完整模型接口仍需使用开发服务，静态预览没有分析 API。

ReAct 一题通常需要多次模型请求，批量评测容易触发万擎 RPM 限制。HTTP 429 会依据服务端提示等待重试，最多 2 次限流重试，并保留记录；超过等待或分析上限才回退为演示模式或返回错误。
